# ADR 0008: Remote sessions (view/control, control lease, revoke)

Sana: 2026-10-30 · Holat: qabul qilingan · Kontekst: P1d · Reja: [p1d-remote-sessions](../superpowers/plans/2026-10-30-p1d-remote-sessions.md)

## Maqsad

Teacher o'z darsidagi qurilmaga `view` yoki `control` remote desktop sessiyasini ochadi; bitta qurilmani bir paytda bitta boshqaruvchi boshqaradi; sessiya yangilanmasa, dars tugasa, qurilma darsdan chiqsa yoki teacher yopsa gateway soketlari uziladi va MeshCentral principal'i o'chadi; API qayta ishga tushsa osilib qolgan sessiya va principal'lar tozalanadi (spec §5.2, §8–§10, §15.1). P0b gateway'i (ADR 0003) API'ga ulandi; brauzer hamon hech bir MeshCentral credential'ini ko'rmaydi.

## Qarorlar

- **Gateway API jarayonida.** `packages/session-gateway` broker/registry/ticket'lari `RemoteGateway` (`apps/api/src/modules/remote-sessions/remote-gateway.ts`) orqali API ichida, ikkinchi HTTPS listener'da (`GATEWAY_PORT`, default 8444; API bilan bir xil TLS). Alohida servis emas: registry xotirada, shuning uchun revoke soketni darhol `terminate()` qiladi va sessiya holati bilan registry orasida tarmoq/RPC sinxronizatsiyasi yo'q. Teacher web bilan **bir host, boshqa port**: gateway cookie'si (`SameSite=Strict`) same-site ishlaydi, lekin origin alohida bo'lgani uchun viewer'ning absolyut yo'llari (`/scripts/`, `/control.ashx`, `/`) teacher web yo'llari bilan to'qnashmaydi (ADR 0003 framing sharti). Config: `GATEWAY_PUBLIC_ORIGIN` (bare https origin; `MESHCENTRAL_URL` berilsa majburiy), `GATEWAY_PORT` `API_PORT`dan farqli; MeshCentral sozlanmagan bo'lsa gateway ishga tushmaydi va ochish 409 `capability_unavailable`. Gateway hodisalari (`route_denied`, `frame_dropped`, `ticket_rejected`, `upstream_error`) Nest logiga yoziladi; ticket va cookie qiymatlari logga tushmaydi.
- **Holatlar va yopilish sabablari.** `opening → active → closed` va `opening → closed`; yopilgan sessiya qayta ochilmaydi. `close_reason`: `teacher` (egasi), `admin` (`remote.manage`), `lesson_ended`, `device_left`, `lease_expired`, `upstream_failed`, `restart`. DB check `status = 'closed' ⇔ closed_at va close_reason bor`. Yopish **har doim DB'da** (`closeRemoteSessions`, chaqiruvchining tranzaksiyasida): sessiya `closed`, lease o'chadi, `remote_session.closed` event, `remote_session.close` audit (timeout/restart'da actor null) va outbox `remote.revoke`. Lock tartibi: avval sessiya qatorlari, keyin xona lock'i (`EventLog`); `endLesson` va qurilma chiqishi (`#leaveLesson`) o'z xona voqeasidan oldin shuni chaqiradi — aks holda aktivatsiya (sessiya → xona) bilan deadlock bo'lardi.
- **Ruxsat.** Org/site admin — `remote.view`, `remote.control`, `remote.manage`. Teacher — `view`/`control` faqat o'z xonasidagi **o'z darsida** (`ownerUserId`); boshqaning sessiyasini yopa olmaydi. it_support va student — hech biri (P1d sessiyalari dars doirasida). Ticket faqat sessiya egasiga: admin ham boshqaning sessiyasiga ticket ololmaydi (yopishi mumkin). Begona/noma'lum ID — bir xil audit qilingan 403.
- **Ochish darvozasi tartibi.** `POST /lessons/{id}/remote-sessions` (`Idempotency-Key` majburiy): saqlangan kalit bo'lsa darvozasiz sessiyaning joriy holati (ADR 0006 "Takroriy so'rov oldindan"). Aks holda tartib bilan: dars `active` va ruxsat → qurilma darsning faol a'zosi (retired emas; aks holda 403) → MeshCentral sozlangan, site'da `mesh_domain_id` va qurilmada `mesh_bindings` bor (aks holda 409 `capability_unavailable`) → Companion hisobotida `remote.desktop` kaliti bo'lsa `state === 'available'` shart (kalit yo'q — manba MeshAgent, ruxsat) → MeshCentral snapshot'ida `agentOnline` (aks holda 503 `device_offline`) → `control` bo'lsa lease (aks holda 409 `control_busy`). **`agentOnline` tranzaksiyadan oldin o'qiladi:** MeshCentral chaqiruvi tranzaksiya va qator lock'larini ushlab turmasligi kerak. 403 (a'zolik) offline/capability xatolaridan oldin tekshiriladi. Online holati o'qish paytidagi suratdir: undan keyin agent uzilsa sessiya baribir ochiladi; renew qilinmasa 30 s'da yopiladi. Bedeli: band qurilmaga har `control_busy` urinishida bitta ortiqcha MeshCentral o'qishi — lease baribir tranzaksiyada, tashqi o'qishdan keyin olinadi; `control_busy`da principal ham, MeshCentral yozuvi ham yo'q, tranzaksiya (sessiya va idempotency kaliti bilan) qaytariladi. Tranzaksiya (dars `FOR SHARE`, a'zolik qatori `FOR SHARE`) `opening` sessiyani yozgach commit'dan keyin `RemoteGateway.open` principal yaratadi, so'ng `UPDATE … WHERE status = 'opening'` bilan `active`; 0 qator (oraliqda dars tugagan yoki qurilma chiqqan) — principal darhol revoke. Upstream xatosi: `upstream_failed` bilan yopish (lease bo'shaydi) va 503 `upstream_unavailable`. Bir jarayonda sessiya aktivatsiyasi bitta va'da orqali: takroriy so'rov uni kutib joriy holatni oladi.
- **Principal nomi.** `ns-sess-<sessionId>` (`sessionId` — `remote_sessions.id`; adapter `^[A-Za-z0-9-]{1,64}$` ni talab qiladi, aks holda `TypeError` va MeshCentral'ga murojaat yo'q; UUID emas, chunki mavjud contract testlar `s-1` kabi id'lardan foydalanadi, API esa doim UUID beradi). `users` ro'yxati `tag` bo'yicha moslashtiriladi: MeshCentral muvaffaqiyatda `responseid` emas `tag` qaytaradi, huquq yetmasa esa `responseid` bilan rad javobi beradi — shuning uchun so'rov ikkala kalitni yuboradi va rad javobi so'rovni `upstream_rejected` bilan tugatadi. Ro'yxatni adapter faqat `ns-sess-` prefiksli user'lardan tuzadi: boshqa MeshCentral user'iga NetSchool tegmaydi.
- **Control lease.** 30 s, client har 10 s `renew` qiladi (`CONTROL_LEASE_MS`, `REMOTE_RENEW_INTERVAL_MS`). `control_leases` PK `device_id`: bitta qurilmada bitta lease. Olish: `INSERT … ON CONFLICT (device_id) DO UPDATE … WHERE control_leases.expires_at <= now RETURNING` — qator qaytmasa 409 `control_busy`; parallel olishda PK to'qnashuvi commit'gacha kutadi va shartni qayta tekshiradi (real PostgreSQL testi). Har olishda yangi `fencing` (`control_fencing_seq`, global monoton, API'da string). `view` lease talab qilmaydi (bir nechta `view` + bitta `control` mumkin). **Renew** (`POST /remote-sessions/{id}/renew`, faqat egasi) bitta tranzaksiyada sessiya `expires_at`ini (`status = 'active' AND expires_at > now`) va `control` bo'lsa lease'ni (`fencing` mos va `expires_at > now`; `numeric` bilan solishtiriladi) uzaytiradi; birortasi 1 qator bermasa 409 `conflict` va hech narsa uzaymaydi. Natijada lease'i boshqaga o'tgan eski controller (eski fencing) yoki muddati o'tgan sessiya hech narsani uzaytira olmaydi. `view` sessiya ham 30 s muddatga ega va xuddi shunday renew bilan uzayadi. `control` renew'da `fencing` majburiy. Renew va ticket audit emas. Muddati o'tgan lease'ni maintenance (har 1 s) `lease_expired` bilan yopadi: Companion yo'qolsa ham qurilma 30 s ichida bo'shaydi.
- **Ticket.** `POST /remote-sessions/{id}/ticket` — alohida endpoint (200, `cache-control: no-store`), faqat egasiga; sessiya `active`, muddati o'tmagan va `RemoteGateway.isOpen` bo'lishi shart (aks holda 409). Ticket (32 bayt, 30 s, bir marta — ADR 0003) DB'ga, auditga, logga va `Idempotency` javobiga **yozilmaydi**: ochish javobi ticket'siz, replay sessiyaning joriy holatini qaytaradi. Sabab: ticket bir martalik credential, uni saqlash replay orqali qayta-qayta berishni anglatardi. Reload kirish yo'lida rad etiladi (ADR 0003), shuning uchun reload yoki yo'qolgan redeem — client yangi ticket so'raydi. Brokerning `open`da bergan birinchi ticket'i ishlatilmaydi (faqat hash, xotirada ≤30 s). URL: `${GATEWAY_PUBLIC_ORIGIN}/rs/redeem?ticket=…`.
- **Revoke outbox orqali.** Yopilish tranzaksiyasi `remote.revoke` ni outbox'ga yozadi, commit'dan keyin chaqiruvchi `kick()` qiladi: worker keyingi 250 ms tick'ni kutmaydi. Handler gateway soketlarini 1008 bilan yopadi va principal'ni o'chiradi; maqsad commit'dan keyin **≤ 2 s** (contract testi real MeshCentral'da `ending the lesson closes viewer sockets within two seconds…`). Noma'lum yoki allaqachon yopilgan sessiya — muvaffaqiyat, gateway o'chiq — no-op, xato — outbox backoff bilan qayta uriniladi.
- **Outbox (P1d o'zgarishi, ADR 0006 ga qarang).** Handler'lar claim tranzaksiyasidan **tashqarida** ishlaydi — tashqi (MeshCentral) chaqiruvlar tranzaksiya va ulanishni ushlamasin. Claim qisqa tranzaksiyada `FOR UPDATE SKIP LOCKED` bilan oladi va `next_attempt_at = now + 30 s` (claim lease) bilan commit qiladi. Qarorlar: (1) **claim urinish hisoblanadi** (`attempts + 1`): jarayonni har safar yiqitadigan qator 10 claim'dan keyin to'xtaydi; (2) kechikkan xato claim tokeni bilan himoyalangan (`next_attempt_at = <claim-lease>` shartli `UPDATE`): lease tugab qatorni boshqa tick olgan bo'lsa, eski xato uning lease'ini qisqartirmaydi; kechikkan muvaffaqiyat esa baribir `processed_at` yozadi (handler'lar idempotent); (3) batch handler'lari **chegaralangan pool**da (16 ta) bajariladi: bitta osilgan MeshCentral revoke boshqa sessiyalarning soketini yopishni kechiktirmasin; (4) claim lease tugagan qatorlar handler'dan oldin o'tkazib yuboriladi (keyingi claim ularni oladi, ikki marta ishlamaydi); (5) `remote.revoke` handler'i **10 s** bilan cheklangan — claim lease (30 s) ichida tugashi uchun; vaqt tugasa broker'dagi revoke to'xtamaydi, keyingi urinish o'sha jarayondagi revoke'ni kutadi; (6) batch qatorlari **tartibsiz** (parallel) bajariladi — kelajakdagi tartib talab qiladigan topic'lar buni hisobga olishi shart. Kafolat at-least-once: jarayon claim'dan keyin o'lsa qator lease tugagach qayta olinadi.
- **Reconciliation** (`RemoteReconciler`). *Startup* (`onApplicationBootstrap`, gateway `listen`dan oldin; main.ts `app.listen`dan keyin gateway'ni ochadi): gateway registry'si xotirada, shuning uchun hech bir sessiya tirik emas — yopilmagan hamma sessiya `restart` bilan yopiladi (lease'lar o'chadi, revoke kick qilinadi). *Principal o'tishi* har doim bir xil qoida bilan: faqat sessiyasi `closed` yoki DB'da yo'q principal o'chiriladi, `opening`/`active` sessiya principal'iga tegilmaydi. "Startda hammasini o'chirish" ishlatilmadi: u kech bajarilsa startdan keyin ochilgan sessiyalarni o'ldirardi; startda esa pre-startup sessiyalar baribir shu paytga kelib yopilgan. Ro'yxat DB so'rovidan **oldin** olinadi (ro'yxatdagi principal'ning `opening` qatori undan oldin commit qilingan). *Retry:* startda MeshCentral control ulanishi odatda hali tayyor emas (main.ts uni kutmaydi — boot kechikmasin), shuning uchun ro'yxatlash xatosi backoff bilan qaytariladi: 5 s → 10 s → … 60 s, birinchi muvaffaqiyatdan keyin har 5 daqiqada. Bu tutib qolgan yetim principal'lar birinchi muvaffaqiyatli ro'yxatgacha (odatda soniyalar) MeshCentral'da qolishi mumkin degani. Ochilish paytida yopilib, revoke principal yaratilishidan oldin ishlagan sessiyaning principal'i ham shu o'tishda tozalanadi.
- **DB yaxlitligi.** `remote_sessions`: `(site_id, lesson_id)`, `(site_id, device_id)`, `(site_id, room_id)→rooms`, `(organization_id, actor_user_id)` FK'lar; mode/status/reason check'lar; partial indekslar (`expires_at`, `lesson_id`, `device_id` — `status <> 'closed'`; maintenance sweep va dars/qurilma bo'yicha yopish ular orqali). `control_leases` sessiyaning **o'z qurilmasiga** bog'langan: `(session_id, device_id)→remote_sessions(id, device_id)` (shuning uchun `remote_sessions(id, device_id)` unique) va `(organization_id, device_id)→devices` — lease boshqa qurilma uchun yozilmaydi. DB yopilgan sessiyada lease bo'lishini taqiqlamaydi: `closeRemoteSessions` uni o'chiradi. `organization_id` dars/qurilma org'iga DB darajasida bog'lanmagan (P1c `commands`/`lesson_devices` bilan bir xil shakl) — servis uni darsdan oladi.
- **Events va audit.** `remote_session.opened|closed` xona oqimida (`data`: `sessionId`, `deviceId`, `mode`, `reason?`); `GET /events` snapshot'ida faol darsning yopilmagan sessiyalari (`remoteSessions`, `opened_at` bo'yicha). Audit: `remote_session.open` (`mode`, `deviceId`), `remote_session.close` (`reason`). Gateway hodisalari auditga emas, logga.
- **Compose.** `meshcentral` konteyneri ([entrypoint.sh](../../infra/meshcentral/entrypoint.sh)): config render → `secrets/meshcentral_service_password` bilan `netschool-svc` service account'i yo'q bo'lsa yaratiladi va site admin qilinadi (**idempotent**: mavjud account'ga va parolga tegilmaydi; yarim qolgan birinchi ishga tushish ham tiklanadi) → `root-cert-public.crt` paydo bo'lgach (≤120 s) `meshcentral-ca` volume'ga atomik nusxalanadi → server. API'ga **faqat public CA** beriladi (read-only volume); `meshcentral-data` (private key'lar) api'ga mount qilinmaydi. Sertifikat nomi **`meshcentral`** ga qotirilgan (`.env`dan olib tashlandi): API `wss://meshcentral:4430`ga hostname tekshiruvi bilan ulanadi, boshqa nom uni buzadi; TLS tekshiruvi o'chirilmaydi. **`trustedProxy` — qat'iy api IP'si, DNS nomi emas:** MeshCentral bitta satrli qiymatni ishga tushishda bir marta DNS orqali aniqlaydi (`webserver.js:7216-7217`), `api` esa meshcentral healthy bo'lgandan keyin ko'tariladi — nom `ENOTFOUND` bo'lib, `X-Forwarded-For` hech qachon ishonilmaydi va barcha gateway foydalanuvchilari `maxInvalidLogin`/`cookieIpCheck` uchun bitta (api konteyner) IP bo'lib qolardi. Shu sabab compose'da `hub` tarmog'i qat'iy subnet (`HUB_SUBNET`, `172.31.250.0/24`) va dinamik diapazon (`HUB_DYNAMIC_RANGE`) bilan, `api` qat'iy `API_IP` (`172.31.250.10`, dinamik diapazondan tashqarida) da; `render-config.mjs` IP literal talab qiladi. `meshcentral` healthcheck: CA fayli bor va 4430 shu CA hamda cert nomi bilan TLS javob beradi; `api` `depends_on: meshcentral healthy`. Faqat `443` va `8444` publish qilinadi; MeshCentral portlari yo'q.
- **Health.** `GET /api/v1/healthz` → `{ status, db, mesh: 'ok' | 'down' | 'disabled' }`; `mesh` adapter control ulanishi holati (`MeshControlClient.connected`). Status faqat DB'ga bog'liq: `mesh: 'down'`da ham HTTP 200 — API MeshCentral'siz ishlaydi va fonda qayta ulanadi.
- **Yangi error kodi:** `control_busy` 409.

- Control'ni majburan olib qo'yish (takeover) — band qurilmada faqat 409 `control_busy`; lease muddati tugagach olinadi.
- it_support uchun darsdan tashqari sessiya (hozir it_support remote'da hech narsa qila olmaydi).
- Gateway hodisalarini auditga yozish — hozir faqat log.
- Bir nechta API replikasi (quyida).
- P1f: teacher web iframe/framing, viewer'ni web ichiga joylash (ADR 0003 framing sharti), `packages/remote-viewer`, renew taymeri.
- P0c'ga qolgan real agent tekshiruvlari (ADR 0003 ro'yxati): view-only'da kiritish haqiqatan agentga yetmasligi, WebRTC o'chiqligi, relay text-kadr allowlist'ining to'liqligi, `tsid`. Contract testlarda agent yo'q: `agentOnline` darvozasi harness'da soxta (MeshCentral o'zi, principal va gateway real), real darvoza faqat unit testlarda.

## Ma'lum cheklovlar

- **Bitta API jarayoni.** Gateway (registry, soketlar), outbox worker va notifier bir jarayonda: revoke handler'i soketni faqat shu jarayonning registry'sida yopa oladi, startup reconciliation "hamma sessiya tirik emas" farazi ham shunga tayanadi. Bir nechta replika uchun sessiyalarni umumiy registry/sticky routing va umumiy uyg'otish kerak bo'ladi (ADR 0006 cheklovi saqlanadi).
- **Lease'ni boshqa sessiya olganda oldingi sessiya darhol yopilmaydi.** Muddati o'tgan lease'ni boshqa controller olganda eski sessiya inline yopilmaydi: uni keyingi maintenance sweep (`lease_expired`, ≤ ~1 s) yopadi (`taken-over session is closed by the next maintenance tick`).
- **Snapshot/view lease'ni sweep'gacha ko'rsatadi.** Muddati o'tgan, lekin hali sweep yopmagan sessiyaning lease'i `view`/snapshot'da turadi; client `lease.expiresAt` ni o'qishi shart, lease mavjudligiga tayanmasin.
- **Eski pilot volume'ni yangilash.** `MESHCENTRAL_CERT_NAME` boshqa qiymat (masalan `hub.school.lan`) bilan yaratilgan `meshcentral-data` volume'ida web sertifikat `meshcentral` nomiga qayta chiqarilishi kerak (aks holda API hostname tekshiruvi yiqiladi). Yangi o'rnatishda muammo yo'q.
- **Service account paroli almashtirish.** `secrets/meshcentral_service_password` ni almashtirish mavjud account parolini o'zgartirmaydi: avval MeshCentral'da `--resetaccount` (server to'xtagan holatda), keyin fayl ([compose README](../../infra/compose/README.md)).
- **`maxInvalidLogin.exclude` faqat loopback** (`127.0.0.1,::1`). Compose'da gateway `API_IP`dan keladi va ishonchli proksi sifatida `X-Forwarded-For`ni beradi, lekin service account (`netschool-svc`) login'lari ham shu IP'dan: ketma-ket xato parol MeshCentral'da API IP'sini bloklashi mumkin. Boshqa foydalanuvchilar `X-Forwarded-For` orqali alohida hisoblanadi.
- Outbox batch'i 100 qatorgacha: hammasi 10 s osilsa (~70 s > 30 s lease) oxirgi qatorlar qayta claim qilinadi va `attempts` oshadi. Crash sababli to'xtagan (10-claim lease'i o'tgan) qator log qilinmaydi — DB'da `attempts = 10` bilan qoladi.
- Contract testlar MeshCentral'ning birinchi login'idagi startup poygasiga sezgir (ADR 0003): reconciliation retry testi byudjeti vaqtga bog'liq, CI'da flake xavfi bor.
- CI `compose-smoke` (healthz `mesh: "ok"`) push'dan keyin tasdiqlanadi; lokal tekshirilgan.
